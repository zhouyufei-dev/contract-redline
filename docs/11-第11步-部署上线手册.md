## 2. 装 Git（一次性）

**已经装好了（2026-11-03，git 2.56.0.windows.4）。** 下面留着，换电脑时照做。

你的电脑上还没有 Git，先装：

```powershell
winget install --id Git.Git -e --source winget
```

装完**关掉 PowerShell 窗口再重开**（不重开识别不到新命令），然后验证：

```powershell
git --version
```

看到 `git version 2.x.x` 就成了。

> **实测记录：这条路当天走不通。** winget 版本是 v1.2（2022 年的），
> 报 `0x8A150002`；直接连 github.com 也超时（下载卡在 17MB）。
> 最后是用**国内镜像 + 官方哈希校验**装上的。换台机器遇到同样情况，照下面做：

```powershell
# 1. 从官方 API 拿到这个版本的 SHA-256（api.github.com 通常仍能通）
(Invoke-RestMethod "https://api.github.com/repos/git-for-windows/git/releases/latest").assets |
    Where-Object { $_.name -like "Git-*-64-bit.exe" } |
    Select-Object name, size, digest

# 2. 从镜像下载（npmmirror 最快，清华 / 南大同理）
curl.exe -L --continue-at - -o "$env:TEMP\Git-setup.exe" `
  "https://registry.npmmirror.com/-/binary/git-for-windows/v2.56.0.windows.4/Git-2.56.0.4-64-bit.exe"

# 3. 先校验再安装 —— 镜像不是官方，必须对哈希，不对就删掉
(Get-FileHash "$env:TEMP\Git-setup.exe" -Algorithm SHA256).Hash

# 4. 静默安装（/EDITOR=notepad：默认编辑器是 Vim，小白会卡在里面出不来）
Start-Process "$env:TEMP\Git-setup.exe" -Wait `
  -ArgumentList "/VERYSILENT","/NORESTART","/NOCANCEL","/SP-","/EDITOR=notepad"
```

**为什么要哈希：** 镜像可以把安装包换成任何东西。哈希和官方一致，
才能证明这个 exe 就是 git-for-windows 发布的那一个。

## 3. 把项目变成 Git 仓库并提交

`git` 是"版本存档"工具，GitHub 是"存档放云端"的地方。先存档，再上传。

### 3.1 先设一次身份（只做一次）

```powershell
git config --global user.name  "你的名字"
git config --global user.email "you@example.com"
```

这两行会写进每一个 commit。邮箱用你真实在用的，GitHub 上会显示它。

### 3.2 用脚本提交（推荐）

我写了一个脚本，它替你做三件事，**并且会在密钥要泄露时硬停下来**：

```powershell
cd C:\Users\Administrator\OpenWorker\6bf4bff0-8bc\contract-redline
powershell -ExecutionPolicy Bypass -File tools\git_first_commit.ps1
```

脚本会：

1. 建仓库（`git init -b main`）
2. **先问 git 本人**确认 `.env`、`.venv`、`.streamlit/secrets.toml`、`data/cache`
   真的被忽略（不是靠肉眼读 `.gitignore`）
3. 暂存所有文件，再逐个检查暂存区，发现 `.env` / `secrets.toml` / `.pem` / `.venv`
   就**清空暂存区并中止**，不产生 commit
4. 打印将提交的文件清单，然后提交

想知道这个"拦截"到底靠不靠谱，可以单独跑它的测试（28 项，不碰你的仓库）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\\test_git_guard.ps1
```

> 为什么要这么防：这个仓库马上要推到**公开**的 GitHub。
> 密钥一旦进了公开仓库，就算下一秒删掉 commit 也没用 —— 它已经进了别人的
> clone 和 GitHub 的缓存。唯一的办法是**根本别提交**。

### 3.3 如果你想手动做（理解原理用）

```powershell
git init -b main
git add .
git status
```

**`git status` 必须亲眼看**：列表里不能有 `.env`，也不能有 `.streamlit/secrets.toml`。
出现了就立刻停下，说明 `.gitignore` 没生效。

```powershell
git commit -m "Contract Redline MVP: rule engine, report, web UI, paywall"
```

> `init` = 建档案柜，`add` = 放进待存档区，`commit` = 封存一个版本。
> 以后每次改代码，重复 `git add .` + `git commit -m "说明"` 就行（或者再跑一次那个脚本）。

> 第 8 节切正式收款前弄好就行。

### 5.2 创建应用

1. 打开 <https://share.streamlit.io>，用 GitHub 账号登录
2. **New app** → **Deploy a public app from GitHub**
3. 填：
   - Repository：`你的用户名/contract-redline`
   - Branch：`main`
   - **Main file path：`app/web/streamlit_app.py`** ← 这一行最容易填错，必须一字不差
   - App URL：自己起个名，比如 `contract-redline`
4. 点 **Advanced settings**：
   - **Python version：3.12**（代码用到 3.11+ 的语法，选 3.10 或更低会直接报错）
   - **Secrets**：把下面 3 行粘进去（值的来源见 5.2.1）

```toml
DEEPSEEK_API_KEY = "sk-你的DeepSeek密钥"
STRIPE_SECRET_KEY = "sk_test_你的测试密钥"
STRIPE_PAYMENT_URL = "https://buy.stripe.com/test_你的测试链接"
```

**5.2.1 三个值分别从哪拿（别猜，照抄）**

| 键 | 去哪里取 | 长什么样 |
|---|---|---|
| `DEEPSEEK_API_KEY` | platform.deepseek.com → API keys | `sk-` 开头，35 位左右 |
| `STRIPE_SECRET_KEY` | Stripe → Developers → API keys → **Secret key**（先确认左上角是 Test mode） | `sk_test_51...` |
| `STRIPE_PAYMENT_URL` | Stripe → Payment links → 你那条 $5 链接 → 点 Copy | `https://buy.stripe.com/test_...` |

> 你本地 `.env` 里就是这三个的真实值，直接**逐行复制**最不容易错。
> （你的 `.env` 里还有 `DEEPSEEK_BASE_URL` 和 `DEEPSEEK_MODEL` 两行 —— 我核对过，
> 它们的值就是代码里的默认值，云端**不用填**。填了也不错，只是多余。）
> 注意：`STRIPE_SECRET_KEY` 是**服务端密钥**，只能放在这里，绝不能出现在网页源码里 ——
> 它一旦泄露，别人就能查你所有订单。
> `STRIPE_PAYMENT_URL` 不是秘密（它本来就要印在按钮上），放这里只是为了让测试/正式切换只改一行。

> 云上**没有 `.env` 这个文件**（它是本地的、永远不会被上传）。云端只认这个 Secrets 框。
> 代码已经改成三个来源都认：环境变量 > Secrets > `.env`。
> 不用 Secrets 的话网站能打开，但会静默失去 DeepSeek 和 Stripe —— 解释变成规则原文、付款永远验不过。
> 这个坑我在附录 A 里写了，也已经用测试锁住了。

5. 点 **Deploy**。第一次构建约 3–5 分钟（要装依赖）。

打开 `https://你的应用名.streamlit.app`，逐条对：

- [ ] 首页能打开，标题是 "Know what you are signing"
- [ ] 底部能点开 Terms / Privacy / Refund / Pricing 四个页面
- [ ] 页脚写的是 `Contract Redline`、`Kowloon, Hong Kong SAR`、`support@contractredline.io`（不再有方括号）
- [ ] 上传框下面写 `20MB per file`，再下面一行也写 `up to 20 MB`（两处一致）
- [ ] 上传假合同 → 只出 1 张卡 + 付费面板
- [ ] 点 `$5` 按钮 → 能跳到 Stripe（此时还是测试模式，有橙色 TEST MODE 条）

### 5.4 让 `contractredline.io` 指向应用（可选，但建议做）

Streamlit 免费版**不支持绑定自定义域名**，只能用 `xxx.streamlit.app`。
能做到的是"短链跳转"：访问 `contractredline.io` 自动跳到应用。

1. Cloudflare → 你的域名 → **Rules → Redirect Rules → Create rule**
2. 名称：`to-app`
3. 匹配：`URI Path` `equals` `/`（或者用 wildcard `*` 覆盖所有路径）
4. 跳转类型：**Dynamic**，表达式：

```
concat("https://你的应用名.streamlit.app", http.request.uri.path)
```

> 用 Dynamic 而不是固定地址，是为了让 `contractredline.io/terms` 也能跳到
> `xxx.streamlit.app/terms`。写死成首页会让法律页面的链接全部失效。

**一句实话：** 这是短链，不是真域名。跳转完成后地址栏显示的仍然是 `xxx.streamlit.app`。
想要地址栏真显示 `contractredline.io`，只能换 Render（$7/月）并绑定域名 ——
等有收入再说，现在不值得。

## 10. 常见故障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 部署后 `ModuleNotFoundError: No module named 'app'` | 启动目录不对 | 已在 `streamlit_app.py` 顶部加了路径引导；若仍报错，检查 Main file path 是否填成 `app/web/streamlit_app.py` |
| 页面能开，但解释是干巴巴的规则原文 | Secrets 里没有 `DEEPSEEK_API_KEY` | Settings → Secrets 补上，保存重启 |
| 付了钱不解锁，顶部红字提示验证失败 | Secrets 里是测试密钥但付的是正式链接，或反过来 | 两者必须是同一个模式（都 test 或都 live） |
| 付完跳转到 `localhost:8501` 打不开 | Stripe 成功跳转地址没改 | 见 8.3 |
| `20MB per file` 又变回 `200MB` | `.streamlit/config.toml` 没被提交 | `git status` 看这个文件在不在仓库里 |
| 上传 20MB 以内也报错 | 云端内存不足（1 GB）解析超大 PDF | 让用户换成 DOCX，或降到 10MB |
| 构建失败 `Could not find a version that satisfies streamlit` | Python 版本选太低 | Advanced settings 改成 3.12 |

## 附录 A：这一步我预先修掉的四个云端专属问题

这四个问题在本地全都不会出现，但上线当天一定会出现。记在这里，是因为它们解释了为什么代码和上周"看起来一样"却更稳了。

1. **云端没有 `.env`，密钥全丢。**
   `app/config.py` 原来只读 `.env` 和环境变量。云端只认 `st.secrets`。
   现在三个来源都读，优先级：环境变量 > Secrets > `.env`。
   *（顺带发现：Streamlit 会把 secrets 也写进环境变量，所以我按实测行为定的优先级，不是按文档猜的。）*

2. **磁盘缓存会把客户的合同条款留在服务器上。**
   LLM 层原来默认开启缓存，把每条解释连同**条款原文**写进 `data/cache/llm/`。
   单机开发时这是省钱神器；一旦对公网开放，就是"每份合同都留了个副本在磁盘上"，
   而页面明明白白写着"扫描完立刻删除"。
   **网页路径已关闭缓存**（命令行调试仍然开着），并加了测试防止以后被改回来。

3. **云端从别的目录启动，`import app` 会失败。**
   已加路径引导，并写了一个"从系统临时目录启动"的探针脚本验证通过。

4. **云端只装 `requirements.txt`，不装 `requirements-web.txt`。**
   而 `requirements.txt` 里原来**没有 streamlit** —— 部署必定失败。已补上。

另外加了一条：`.streamlit/secrets.toml` 进了 `.gitignore`，防止你把密钥文件误传上公开仓库。
