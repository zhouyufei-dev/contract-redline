# 第 8 步：极简网页前端（Streamlit）

一句话：**把终端里那套流水线，原封不动地搬到一个网页上。** 用户在浏览器里传一份合同，点一下按钮，就能看到第 7 步那份排版好的报告。

---

## 1. 怎么启动（你只需要记这两行）

在项目根目录（`contract-redline`）打开 PowerShell，敲：

```powershell
.\web.ps1
```

然后浏览器打开：

```
http://localhost:8501
```

就这两步。

- 想停掉：在 PowerShell 窗口里按 `Ctrl + C`。
- 8501 端口被别的软件占了（会报 `Port 8501 is already in use`）：换一个端口 `.\web.ps1 -Port 8600`，网址相应变成 `http://localhost:8600`。
- 第一次运行会自动装 Streamlit（约 50 MB），只装一次，之后启动只要两三秒。
- 如果 PowerShell 提示"禁止运行脚本"，先执行一次：
  `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

不想用脚本也行，等价命令是：

```powershell
.\.venv\Scripts\python.exe -m streamlit run app/web/streamlit_app.py
```

## 2. 页面上有什么

从上到下，只有四样东西，**故意只留四样**：

| 位置 | 内容 |
|---|---|
| 标题 | `Know what you are signing.` |
| 说明 | 一段话，讲清楚"传合同 → 看红旗 → 知道要改什么" |
| 上传框 | 一个大虚线框，只收 PDF 和 DOCX，最大 20 MB |
| 按钮 | `Scan My Contract` |

再加一行小字（PDF 或 DOCX · 20 MB · 文件扫完即删 · 这不是法律建议），和一个默认打开的开关 **Write plain-English explanations**。

这个开关是给两种情况留的：没配 API Key，或者你只想看规则引擎自己的措辞。关掉它，**抓出来的红旗一条不多一条不少**，只是卡片里的解释文字换成我们手写的标准措辞。这是刻意的——AI 从来不决定"有没有风险"，它只负责把话说人话。

点按钮之后，按钮位置会出现一个状态框，一条条往下写：

```
Analyzing your contract…
  Reading the file
  Reading the document and checking 20 red-flag clauses
  Writing plain-English explanations for each problem
  Laying out your report
```

这些文字不是装饰。真实的一份 12 条款合同，规则引擎约 0.01 秒，DeepSeek 写 20 张卡片约 10–15 秒，排版 0.05 秒——**几乎全部时间都花在等 AI**，所以进度必须说实话，而不是转一个假圈。

跑完之后，报告直接嵌在页面里（一个带边框的白色"纸张"），上面有一行小结：

```
20 cards, worst first                      fake_contract_01.docx
3 deal-breakers · 6 serious · 9 costly · 2 to watch.
```

还有两个按钮：**Download the report**（下载这份 HTML，和第 7 步终端生成的是同一个文件）、**Scan another contract**（清空重来）。

## 3. 代码放在哪，为什么这么放

```
app/pipeline.py            ← 新增。四步流水线，没有界面
app/web/uploads.py         ← 新增。上传文件的检查、临时落盘、清理
app/web/streamlit_app.py   ← 新增。只负责画页面
web.ps1                    ← 新增。一键启动
requirements-web.txt       ← 新增。Streamlit（可选依赖，不影响核心）
tools/test_web.py          ← 新增。37 项检查，不需要浏览器、不需要 Key
```

### 关键决定：把流水线抽出来，而不是在 Streamlit 里重写一遍

原来的 `app/main.py`（终端版）里，四步是按顺序写死的：解析 → 匹配 → 合并 → 解释 → 排版。

如果网页版照着抄一遍，就等于**同一套逻辑维护两份**。以后改了合并规则，只改终端那份，网页那份就悄悄落后了——这类 bug 最难发现，因为它不报错，只是结果不一样。

所以新增 `app/pipeline.py`，把四步变成四个函数：

```python
outcome     = pipeline.scan_contract(path)      # 或 scan_text(text)
explanation = pipeline.explain(outcome)          # DeepSeek，永不抛异常
report      = pipeline.build_report(outcome, explanation.cards)
html        = pipeline.render_html(report)
```

终端和网页都只调这四个函数。`app/main.py` 里的那 40 行顺序代码被删掉，换成了调用——**改完之后我拿同一份合同重跑终端，160 行输出逐字一致**（时间数字除外），HTML 报告 61,790 字节，和改之前一样。

`app/web/streamlit_app.py` 里没有一行判断"什么是风险"的代码。它只做三件事：收字节、调 pipeline、把 HTML 塞进 `components.html()`。

## 4. 上传这道关卡（这是最容易被忽略的地方）

用户会传什么，和你以为他们会传什么，是两件事。所以 `uploads.validate()` 在解析之前先挡一道，每条错误都写成**用户看得懂、知道下一步该干嘛**的句子：

| 用户实际做的事 | 我们回的话 |
|---|---|
| 传了个 `.txt` | We cannot read '.txt' files. Please upload a PDF or a DOCX. |
| 把老的 `.doc` 改名成 `.docx` | That file is named .docx but is not a Word document. An old .doc renamed to .docx will not open - save it as .docx in Word. |
| 手机拍的合同，改名成 `.pdf` | That file is named .pdf but is not a PDF. If it came from a Mac or a scanner app, export it again as PDF. |
| 传了 30 MB 的扫描件 | That file is 30 MB. The limit is 20 MB - a contract is normally under 2 MB. |
| 空文件 | That file looks empty. Try uploading it again. |

怎么判断"名不副实"？看文件头两个字节：真 PDF 一定以 `%PDF-` 开头，真 DOCX 是 ZIP 包，一定以 `PK` 开头。改后缀改不掉文件头，所以这一招能挡住"我把 Word 里的图片另存为 pdf 了"这种最常见的误会。

**文件名的处理**：浏览器可能送来 `..\..\etc\passwd.docx` 或者 300 个字符的名字。`safe_name()` 会剥掉所有目录部分、只保留白名单字符（字母数字、空格、点、括号、连字符），并把长度压到 80 字符以内。这样写盘的时候，文件永远落在临时目录里，不可能跑到别的地方去。

**文件的生命周期**：上传的内容写进系统临时目录的一个随机文件夹，扫描结束（无论成功、报错、还是抛异常）都在 `finally` 里整个删掉。报告这时候已经是一个字符串了，**用户的合同不留痕**。这一条写进了页脚的小字里，因为它是一个卖点：客户合同是敏感文件，很多人不敢往陌生网站传。

## 5. 界面为什么长这样

三条规矩，按重要性排：

1. **只留一个动作。** 页面上唯一"看起来能点"的，是 `Scan My Contract`。没有导航、没有侧边栏、没有设置面板、没有示例文件按钮。第一版加得越多，用户越不知道下一步干嘛。
2. **上传框是页面上最大的东西。** 2 像素虚线、34px 内边距、悬停变红。用户进页面第一眼就该知道"把文件放这儿"。
3. **页面和报告是同一个产品。** 强调色 `#b42318` 和报告里的 critical 红是同一个色值；正文用系统无衬线字体（`-apple-system`/`Segoe UI`），和报告一致。Streamlit 自带的汉堡菜单、页脚、顶部工具条全部隐藏——这是个产品页，不是 Jupyter notebook。

按钮是纯黑而不是红色：红色留给"风险"，如果按钮也是红的，整页的视觉重心就跑偏了。

## 6. 测试（`tools/test_web.py`，37 项，不需要 Key、不需要浏览器）

| 组 | 查什么 |
|---|---|
| 1. 上传关卡 | 真 PDF/DOCX 通过；空文件、`.txt`、无后缀、假 DOCX、假 PDF、超 20 MB 各自被拒，且报错话术对得上 |
| 2. 文件名 | Windows 路径、POSIX 路径被剥干净；正常名字（含空格括号）原样保留；超长被截断；空名字有兜底 |
| 3. 临时文件 | 写进去的内容一字不差；退出后文件夹消失；跑完不留下任何新的临时目录 |
| 4. DOCX 全流程 | 20 张卡片、来源文件名正确、HTML 是完整文档、免责声明在里面、全英文、两次跑结果完全一致 |
| 5. PDF 全流程 | 同样 20 张卡片、免责声明在 |
| 6. 进度文案 | 三步（关掉 AI 时两步）、文案里**不含任何文件路径或密钥片段**、全英文 |
| 7. 页面渲染 | 用 Streamlit 官方的 `AppTest` 真的把脚本从头跑一遍：无异常、标题在、按钮在、上传框在 |

第 7 组值得多说一句：`AppTest` 是在没有浏览器的情况下**真的执行整个页面脚本**。它能抓到"某个 Streamlit API 名字写错了"这类错误——那种错误在终端里跑测试永远发现不了，只有用户打开页面才会看到一屏红字。

## 7. 已知限制（说在明处）

- **一次只能扫一份。** 批量、对比、历史记录都不做，这一版不做。
- **不支持扫描件/图片 PDF。** 和第 3 步的边界一致：没有文字层的 PDF 读不出内容，会报"没读到文字"而不是假装扫过。
- **报告在 iframe 里，高度是估算的。** 卡片多了会有内部滚动条。这是 `components.html` 的固有行为，换来的是报告样式和终端版 100% 一致（不受 Streamlit 的 CSS 干扰）。要彻底解决得上自定义组件，不值得。
- **没有账号、没有付费墙、没有限流。** 这是本地跑的原型，不要直接挂公网——一挂上去，API Key 就是别人的了。上线前必须先做：登录、限流、每用户配额。
- **刷新页面结果就没了。** 结果存在 `st.session_state`，刷新即清空（合同不落盘，这是代价也是特性）。
