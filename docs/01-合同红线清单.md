## 一、怎么读这份清单

| 字段 | 含义 |
|---|---|
| **编号** | 规则 ID，直接对应未来代码里的规则文件名 |
| **等级** | 致命(10) / 严重(7) / 高(5) / 中(3)，用于算总分和排序 |
| **可检测性** | `A` 关键词/正则即可命中（高确定性）<br>`B` 需要看上下文/邻近词（±8 词窗口）<br>`C` 需要 LLM 语义复核<br>`D` 缺失检测（全文**找不到**某条款才报，是反向规则） |
| **英文关键词** | 写进规则里的种子词，含常见变体 |
| **为什么是坑** | 给用户看的解释骨架（未来由 DeepSeek Flash 扩写成大白话，但结论不许偏离） |
| **建议改法** | 用户拿去和客户谈判的"标准动作"，同样作为 DeepSeek 生成建议的锚点 |

**重要设计原则（决定项目成败）**：每一条命中都必须带 **evidence（原文整句 + 位置）**。规则引擎只负责"指出来"，LLM 只负责"解释"，**绝不让 LLM 决定"有没有这条风险"**。这样即使解释写得不好，用户看到的引用永远是真的。

## 二、20 条红线

### A. 付款与现金流（自由职业者最常被拖死的地方）

#### R01 · 超长付款周期
- **等级**：严重（7）　**检测**：A
- **英文关键词**：`net 45` / `net 60` / `net 90` / `net 120` / `within (thirty|forty-five|sixty|ninety|one hundred twenty) (30|45|60|90|120)?\s*\(?days?\)?` / `payment terms` / `invoice date`
- **为什么是坑**：行业惯例是 15–30 天。写成 60/90 天，等于你免费给客户提供了一笔 2–3 个月的无息贷款；对方再拖两周，你的房租就出问题了。而且账期越长，客户内部"这单还值不值得付"的变数越多。
- **建议改法**：改成 Net 15 或 Net 30；大项目拆里程碑预付（如 30% 定金 / 40% 中期 / 30% 交付）。

#### R02 · 付款绑定"客户验收/满意"
- **等级**：致命（10）　**检测**：B
- **英文关键词**：`upon acceptance` / `final acceptance` / `written acceptance` / `in Client's sole discretion` / `satisfactory` / `deemed accepted`
- **为什么是坑**：钱什么时候到，取决于客户"点不点头"，而"满意"是主观的、没有标准的。这是最经典的无期限拖欠结构——他可以永远"还不满意"。
- **建议改法**：改为客观验收标准 + **自动视为验收**条款（"若客户在交付后 5 个工作日内未提出具体书面异议，视为验收通过"）。

#### R03 · 背靠背付款（客户收到上家的钱才付你）
- **等级**：致命（10）　**检测**：A
- **英文关键词**：`pay when paid` / `pay if paid` / `upon receipt of payment from` / `end client` / `prime contractor` / `funding is secured`
- **为什么是坑**：你的报酬被绑在一条你完全看不见、也无法控制的付款链上。客户的上家赖账、项目被砍、预算被冻结——任何一个环节出问题，你都拿不到钱，而且法律上很难主张。
- **建议改法**：整条删掉。如果对方是大企业转包、坚持保留，要求"最长不超过发票后 45 天，无论上家是否付款"。

#### R04 · 客户可单方抵扣、扣款、暂扣
- **等级**：高（5）　**检测**：B
- **英文关键词**：`set-off` / `setoff` / `right to deduct` / `withhold` / `offset against` / `charge back`
- **为什么是坑**："抵扣权"通常是单向的：客户觉得有损失就能直接从你的账单里扣，不需要你同意、不需要证据。等于你的发票金额随时可以被单方面打折。
- **建议改法**：删除单方抵扣，或限定为"仅限双方书面确认的、已到期的确定债务"。

### B. 工作范围与修改（利润被吃光的地方）

#### R05 · 无限次修改
- **等级**：致命（10）　**检测**：A
- **英文关键词**：`unlimited revisions` / `unlimited rounds` / `revisions until` / `until Client is satisfied` / `as many revisions as necessary` / `reasonable revisions`
- **为什么是坑**：这是自由职业者亏钱的第一大原因。一个"再来一版"没有上限，项目就永远结束不了，你的时薪会一路跌到负数。而且"修改"和"重做"的边界在合同里往往是模糊的。
- **建议改法**：写死轮次（如"含 2 轮修改"），超出部分按小时计费（写明月费率）；把"重做方向"和"修改细节"分开定义。

#### R06 · 开放式工作范围
- **等级**：高（5）　**检测**：A
- **英文关键词**：`including but not limited to` / `and other duties as assigned` / `as reasonably requested` / `from time to time` / `such other services` / `any other work`
- **为什么是坑**："以及客户合理要求的其他工作"——这一句话可以把整个项目范围变成无限。它把定价权交给了客户：你已经报了价，但工作量由他定义。
- **建议改法**：范围必须封闭式列举（附件 SOW），并写明"任何超出 SOW 的工作需双方书面确认的变更单（Change Order）及额外费用"。

#### R07 · 免费额外工作 / 无上限售后
- **等级**：高（5）　**检测**：A
- **英文关键词**：`at no additional cost` / `at no charge` / `free of charge` / `without additional compensation` / `bug fixes for (six|twelve|24) months` / `ongoing support`
- **为什么是坑**：交付后 6–12 个月的"免费修 bug"听起来合理，但如果"bug"没定义，客户会把所有"想改的地方"都叫 bug。免费维护期越长，你越像在被无限期雇佣。
- **建议改法**：明确"bug = 与已确认需求不符的缺陷"，免费期 14–30 天；之后按维护包或小时计费。

### C. 知识产权与作品使用权（决定你能不能接下一单）

#### R08 · 全部成果（含未采用的方案）无条件转让
- **等级**：致命（10）　**检测**：A
- **英文关键词**：`assign all right, title and interest` / `work made for hire` / `work for hire` / `all deliverables` / `including all concepts, drafts, sketches, unused` / `in perpetuity` / `worldwide`
- **为什么是坑**：注意两点。① 在美国版权法下，"work made for hire" 对独立承包人只覆盖少数几类作品，所以客户往往会再叠一句 assignment——看到两句一起出现，说明对方（或对方的法务模板）很清楚这一点。② 更贵的是"连没采用的方案一起转"：你的创意方法论、你被毙掉的 8 个方案，全都归他了，你下次给别的客户做类似的东西都可能被指"复用"。
- **建议改法**：只转让**最终交付物**且**在付清全款后**生效；明确保留"未被采用的方案、前期草图、通用组件、既有工具与模板"的所有权；给自己保留非独占的作品集展示许可。

#### R09 · 放弃精神权利 / 禁止作品集展示
- **等级**：高（5）　**检测**：A
- **英文关键词**：`moral rights` / `waive` / `shall not display` / `portfolio` / `case study` / `confidential` + `portfolio` / `prior written consent`
- **为什么是坑**：对设计师来说，作品集就是获客渠道。一条"未经书面同意不得展示"就能让你这一整年的代表作消失，直接削弱你下一单的议价能力。而"书面同意"在实践中经常是已读不回。
- **建议改法**：保留"有权在作品集/个人网站展示（可延迟 3–6 个月、可去除敏感信息）"；保密义务不覆盖"作品存在过"这一事实。

#### R10 · 客户可二次开发、转售、用于 AI 训练
- **等级**：高（5）　**检测**：B
- **英文关键词**：`modify, adapt` / `create derivative works` / `sublicense` / `resell` / `train` / `machine learning` / `AI model` / `dataset`
- **为什么是坑**：传统合同写"可修改、可再许可"是为了客户内部使用；但在 2024 年后，同一句话可能被用来把你的作品喂进模型。一旦进入训练集，你就永久失去了对"风格被复制"的控制，且几乎无法追溯。
- **建议改法**：明确"不得用于训练机器学习/生成式 AI 模型"；二次开发限于客户自身业务，不得转售或作为模板产品分发。

### D. 责任与赔偿（一条就能让你破产）

#### R11 · 无上限赔偿（Indemnification）
- **等级**：致命（10）　**检测**：A
- **英文关键词**：`indemnify, defend and hold harmless` / `any and all claims` / `including reasonable attorneys' fees` / `against all losses` / `third-party claims`
- **为什么是坑**：Indemnify 的意思是"对方被告了，你去赔、你去请律师"。如果它没有上限、没有过错前提（比如只写"arising out of the Services"，不管是不是你的错），客户自己的经营风险也会算到你头上。一个 5000 美元的项目，可能带来 50 万美元的索赔。
- **建议改法**：限定为"因你的故意或重大过失导致的第三方知识产权侵权"；加**责任上限**（通常为合同总金额，或已收费用）；排除间接损失；并要求客户对你的"按其指示/按其提供素材"造成的风险负责。

#### R12 · 责任无上限 / 无限制条款
- **等级**：致命（10）　**检测**：D（缺失检测）+ B
- **英文关键词**：`without limitation` / `in no event shall` / 缺失：`limitation of liability` / `aggregate liability` / `shall not exceed` / `consequential damages`
- **为什么是坑**：**合同里没有责任上限，本身就是最大的风险**。默认法律状态下，你的赔偿可能包括对方的利润损失、商誉损失、后续损失。所以这条要"反向查"：全文找不到 limitation of liability，就要报红。
- **建议改法**：加入双向责任上限条款："任一方累计责任不超过本协议项下已支付/应付费用总额；双方均不承担间接、附带、后果性损失。"

### E. 终止、独家与单方变更（把你锁死的地方）

#### R13 · 客户可随时无责终止（且无补偿）
- **等级**：严重（7）　**检测**：A
- **英文关键词**：`terminate for convenience` / `at any time` + `without cause` / `upon written notice` + `no further obligation` / `sole discretion to terminate` / `kill fee`
- **为什么是坑**：客户可以中途叫停，而你已经排掉的档期、拒掉的其他项目、投入的前期研究都收不回来。如果合同还写着"终止后客户无需支付任何费用"，你连已完成的部分都拿不到。
- **建议改法**：要求 kill fee（如已完成阶段全额 + 剩余阶段的 25%–50%）；明确"终止不影响已完成工作的付款义务"；你的反向权利：客户拖欠时你有权停工。

#### R14 · 竞业限制 / 独家服务
- **等级**：严重（7）　**检测**：A
- **英文关键词**：`non-compete` / `noncompetition` / `shall not provide similar services` / `exclusively` / `competitor` / `conflict of interest` / `during the term and for (six|twelve) months`
- **为什么是坑**：对自由职业者来说，"不得为竞品提供服务"等于把自己的客户池砍掉一半，而且期限常常延续到合同结束后 6–12 个月——你没拿到任何补偿，却要放弃一整块市场。
- **建议改法**：删除竞业；如必须保留，限定为"合同期内 + 直接竞品 + 有书面清单"，并要求相应报酬。

#### R15 · 禁止接触客户 / 禁止后续直接合作
- **等级**：高（5）　**检测**：A
- **英文关键词**：`non-solicitation` / `shall not solicit` / `shall not engage` / `directly or indirectly` / `bypass` / `introducing` + `clients`
- **为什么是坑**：你在这单里认识的对接人，未来可能是你的客户。一条宽泛的"不得直接或间接招揽"，可能把你未来几年和这个行业所有人的合作都堵死。
- **建议改法**：限定为"不得主动挖走客户方的在职员工"，不限制你与个人建立独立的、非本项目的合作。

#### R16 · 客户可单方修改合同条款
- **等级**：高（5）　**检测**：A
- **英文关键词**：`may modify these terms at any time` / `reserve the right to change` / `continued performance constitutes acceptance` / `at our sole discretion` + `amend`
- **为什么是坑**：这条把你的合同变成了一份"随时可被改写"的文件。更阴的是"继续履约视为同意"——你埋头干活，就默认接受了新条款。
- **建议改法**：任何修改需双方书面签署；不接受"默示同意"。

### F. 保密、保证与争议解决（签完才发现代价的地方）

#### R17 · 异地管辖 / 强制仲裁 / 败诉方承担律师费
- **等级**：高（5）　**检测**：A
- **英文关键词**：`governed by the laws of` / `exclusive jurisdiction` / `venue` / `arbitration` / `arbitration rules` / `prevailing party` + `attorneys' fees` / `waive` + `jury trial`
- **为什么是坑**：如果对方在另一个州/国家，你去那里打官司的成本可能超过你全部应收款——这意味着你实际上**没有**追讨能力。强制仲裁还要先交几千美元的仲裁费。"败诉方承担律师费"听起来公平，但谁"败诉"由仲裁员决定，风险是双向放大的。
- **建议改法**：改为你所在地的法院管辖，或中立的线上争议解决；小额争议（如 1 万美元以下）保留小额诉讼通道。

#### R18 · 违约金 / 按日罚款
- **等级**：高（5）　**检测**：A
- **英文关键词**：`liquidated damages` / `penalty of` / `per day` / `per diem` + `delay` / `service level` + `credit` / `time is of the essence`
- **为什么是坑**："每晚一天罚 500 美元"是把你放在一个你无法完全控制的时间表上（客户反馈慢、素材不到位，都算你延期），而且罚款可能超过合同金额本身。
- **建议改法**：删除罚款，改为"因你原因导致的延期，双方协商调整交付日"；工期起算点绑定"客户提供全部素材与反馈之日"。

#### R19 · 无限期保密（且覆盖公开信息）
- **等级**：中（3）　**检测**：A
- **英文关键词**：`perpetual` / `in perpetuity` / `survive indefinitely` / `confidentiality obligations shall survive` / `all information` + `whether or not marked`
- **为什么是坑**：保密本身合理，但没有期限、且覆盖"所有信息（不论是否标注为保密）"，意味着你几年后无法证明某个东西是你早就知道的公开知识。它会和 R09（作品集）叠加，形成长期的自我审查。
- **建议改法**：期限 2–3 年（商业秘密除外）；排除公开信息、你独立开发的信息、法律要求披露的信息。

#### R20 · 过宽的保证条款
- **等级**：中（3）　**检测**：B
- **英文关键词**：`warrants that` / `error-free` / `free from defects` / `fit for a particular purpose` / `merchantability` / `comply with all applicable laws` / `uninterrupted`
- **为什么是坑**："保证作品无任何错误、适用于特定用途、符合所有适用法律"——软件不可能无 bug，法律合规也不是设计师能担保的（无障碍、隐私、行业监管）。这种保证一旦成立，等于你为对方的业务合规背书。
- **建议改法**：改为"以行业标准谨慎提供服务，交付物在实质上符合 SOW 约定"；明确不保证特定商业结果；合规责任限于你交付物本身。

## 四、规则引擎实现要点（写代码前必须先看）

1. **否定与例外窗口（最容易被骂的点）**
   合同里常有 `shall not be liable for any...`、`excluding unlimited revisions`。匹配到关键词后，检查前后 8 个词内是否出现 `no / not / shall not / except / excluding / without / provided that`：有就降级为"需人工复核"，而不是直接报红。否则用户第一次用就发现误报，信任直接归零。

2. **数字的两种写法**
   法务模板爱写 `sixty (60) days`。正则要同时覆盖阿拉伯数字和英文单词，并处理 `Net 60`、`Net-60`、`Net sixty (60)` 三种形态。

3. **文本预处理（PDF 提取后必做）**
   去页眉页脚重复行、合并被换行切断的句子、修复 `con-` + `tract` 这类连字符断词、统一 `'` `'` 与 en-dash，再统一 `lower()`。否则正则命中率会掉一大截。

4. **缺失检测（D 类）是另一套逻辑**
   R12 要判断"全文没有责任上限"，需要按"文档级"统计而不是逐句匹配。建议第一批先只做 A/B 类（出现了什么），第二批再做 D 类（缺了什么）——这也是我在下面问题 4 里想跟你确认的。

5. **打分不要简单相加**
   20 条全中会得到 100+ 分，用户无感。建议：`score = 加权和`，然后只展示 **Top 3 风险 + 其余折叠列表**；分数映射成三档行动建议（"建议谈判后再签 / 建议逐条谈 / 可签，注意 X"）。

6. **每条输出必须带 evidence**
   结构建议：`{rule_id, severity, matched_text, sentence, location(page/para), why, suggestion}`。`why` 和 `suggestion` 由 LLM 生成，`matched_text/sentence/location` 永远来自规则引擎。这是"零幻觉"承诺能不能兑现的技术分界线。

7. **免责声明是硬编码，不是 LLM 生成**
   固定文案追加在报告末尾（"This is not legal advice..."），不经过模型，避免它某次"忘了写"。

---

## 五、需要你拍板的 5 件事

1. **解释语言**：目标用户是海外自由职业者，报告正文大概率应该是**英文**（中文只给你自己看）。要不要做成"英文解释 + 中文对照"双语？
2. **市场范围**：以美国为主，还是全球？这直接影响 R17（管辖）和 R08（work for hire）的判读深度。
3. **职业分权重**：设计师更在意 R09（作品集）/ R10，开发者更在意 R08（IP）/ R11（开源与赔偿）。要不要按职业给不同权重？
4. **是否第一批就做"缺失检测"**（如"合同里根本没有责任上限"）：价值很高，但会让规则层复杂一档。我的建议是**第二批**再做。
5. **20 条够不够/多不多**：有没有你想加或想删的？（比如电商/内容创作者常见的"账号归属""平台分成"条款）
