## 1. 你为什么需要这些东西（不是形式主义）

Stripe 开个人账户时，审核的人会做三件事：

1. **打开你填的网址**，看这个站到底卖什么、是不是真的在运营；
2. **找三份文档**：服务条款、隐私政策、退款政策。找不到 = 打回；
3. **看你能不能承担责任**：你是谁、在哪、怎么联系、钱怎么收怎么退。

审核员不读代码，也不测你的规则引擎有多准。他只看"这个网站像不像一个正常做生意的主体"。
所以这一步的目标不是"法律上完美"（那要找香港律师，费用比你整个项目都贵），
而是**诚实、完整、对得上自己的产品行为**——每一句话都能被你在代码里兑现。

### 2.2 这些文本怎么进到网站里

不是复制粘贴成死 HTML，而是：

```
app/site.py            ← 运营主体信息（名称、地址、邮箱、域名）集中一处
app/web/legal/*.md     ← 正文，里面写 {{operator}} 这种占位符
app/web/ui.py          ← 样式 + 页脚（页脚在每一页出现：三份文档链接 + 主体信息）
app/web/pages.py       ← 5 个页面 + 路由表 ROUTES
app/web/streamlit_app.py ← 只做路由，不再放业务代码
```

好处：改一次公司地址，五份文档和页脚同时变；测试可以检查"有没有漏掉的占位符"。

### 2.3 网站现在的结构（这就是 Stripe 会看到的东西）

| 路径 | 页面 | 作用 |
|---|---|---|
| `/` （即 `/scan`） | 扫描首页 | 上传 → 扫描 → 报告，主业务 |
| `/pricing` | 定价 | Stripe 一定会看：卖多少钱、包含什么 |
| `/terms` | 服务条款 | 审核必查 |
| `/privacy` | 隐私政策 | 审核必查 |
| `/refund` | 退款政策 | 审核必查 |

页脚（每一页底部）固定包含：
定价 · 服务条款 · 隐私政策 · 退款政策 · **主体名称 · 地址 · 支持邮箱** · 一句"这是软件不是律所"。

> 为什么费劲做真路由（`/terms` 而不是 `?page=terms`）：审核员（和自动检查脚本）
> 是直接请求 URL 的。一个打不开或 404 的法律页面，等于没有这个页面。

### 2.4 定价页的一个诚实决定

现在没有支付，也没有价格。定价页 **不写假价格**（不写"$9/月 即将上线"那种）。
写的是：当前免费、不限次数、不要卡；付费计划**尚未上线**；上线时会在付款前明示价格。
理由是：Stripe 审核会核对"网站上写的价格"和"账户里填的商品"，两边对不上就是打回。
等支付接好了，把 `_PRICING` 里那几行改成真价格即可（一处改，测试会跟着校验）。

## 5. 还缺什么（这是你现在要动手的部分）

### 5.1 五个占位符 —— 缺了它们，审核 100% 打回

打开 `app/site.py`，把下面 5 项换成真信息：

| 字段 | 现在 | 该填什么 | 注意 |
|---|---|---|---|
| `operator` | `[Your legal name]` | 你的**法定姓名**（与 Stripe 账户、香港身份证/护照一致） | 三个字的中文名 vs 拼音：**必须和银行账户户名一致**，通常用拼音 |
| `operator_type` | `[Individual, Hong Kong]` | 个人身份，例：`Individual, Hong Kong` | 香港个人账户就写个人，不要写成"有限公司" |
| `address` | `[Your address]` | 能收到信的地址 | 香港账户建议写香港地址；没有的话问清楚 Stripe 能不能用大陆地址（见 6.3） |
| `email` | `[you@yourdomain.com]` | **用你自己域名的邮箱**（`support@你的域名`） | Gmail/QQ 邮箱会显得像玩具站，且和域名对不上 |
| `domain` | `[yourdomain.com]` | 真正在跑的那个域名 | 必须和 Stripe 后台填的网址完全一致（含不带 www 的形式） |

填完跑这条命令验收：

```powershell
.\.venv\Scripts\python.exe tools\test_site.py --strict
```

没填完时它会明确报红：`FAIL 5.1 of the launch checklist: placeholders left in app/site.py (...)`；
五项都填好后 `--strict` 会以 **exit 0** 通过。这就是"可以拿去提交审核了"的信号。
（平时开发不加 `--strict`，只打印一行 NOTE，不挡你干活。）

### 5.2 一个公网 HTTPS 域名 —— 现在最大的硬伤

Stripe 审核员在海外，他**打不开 `localhost:8501`**，也打不开你家路由器的内网 IP。
现在这个应用只在你这台机器上活着：

```
Local URL:   http://localhost:8501        ← 只有你能开
Network URL: http://192.168.x.x:8501      ← 你家局域网
External URL: http://103.x.x.x:8501       ← 公网 IP，但：HTTP、IP 直连、随时会变
```

**这三种都不能拿去审核。** 审核要的是：`https://你的域名.com/terms` 点开就有内容。

需要你做的（按省事排序，都是你开户前就能搞定的）：

| 方案 | 成本 | 适合你吗 | 说明 |
|---|---|---|---|
| **A. Streamlit Community Cloud** | 免费 | ✅ 最适合先过审 | 连 GitHub 仓库，一条命令部署，自动 HTTPS + 域名 `xxx.streamlit.app`。缺点：域名带 `.streamlit.app`，可后续绑自有域名 |
| B. Railway / Render | 免费额度或 $5/月 | 可以 | 支持自定义域名更顺，需要绑卡 |
| C. 一台海外 VPS + Caddy | $5/月 | 暂时不必 | 最可控，但要自己运维 |

**我的建议：先用 A 把站点跑起来拿到 HTTPS 链接**，等 Stripe 账户过了、有收入了再迁到自有域名。
理由：审核只关心"能不能打开、内容对不对"，不关心你用什么托管。别为了完美域名卡住开户。

⚠️ 部署到 Streamlit Cloud 时注意两件事：
1. **API Key 放 Secrets**，不要提交 `.env`（`app/config.py` 已经是从环境变量/`.env` 读，Streamlit Cloud 会自动把 Secrets 注入成环境变量）；
2. 免费实例**闲置会休眠**，审核员打开可能等 10–20 秒。可以先用定时任务每天唤醒，或者审核期间选付费小实例。

### 5.3 一个能收信的 `support@` 邮箱

三份文档和页脚都指向 `SITE.email`。Stripe 会真的发一封邮件过去。
用域名邮箱（Google Workspace / Zoho 免费版 / Cloudflare Email Routing 转发到你的常用邮箱都行）。

## 7. 等支付接回来时，网站还要补三样（现在**不要**做）

这三样只有在"真的开始收钱"时才有意义，现在做等于给自己加无用的坑：

1. **结账前的同意勾选框**：`☐ I agree to the Terms of Service and Refund Policy`
   —— 欧盟/英国的 14 天撤回权，只有在用户"明示同意立即交付并放弃撤回权"时才不适用。
   `refund.md` 第 6 节已经这么写了，但**页面上必须真的有一个勾选框**，否则文档和实现对不上。
2. **Stripe 的账单描述符**（statement descriptor）：用户在信用卡账单上看到的一行字，
   建议 `CONTRACTREDLINE`（≤22 字符），要和品牌名一致，否则容易被当成盗刷。
3. **税务页 / 发票说明**：香港个人经营，先确认你适用的利得税/销售税口径；
   定价页要注明"价格不含适用税费，结账时显示"。`terms.md` 第 8 节已经埋了这句话。

另外一条已经处理好的隐患：**DeepSeek 在中国大陆**。
你的用户是美国人，把合同句子发给大陆的模型服务是真实的隐私风险。
`privacy.md` 第 5 节明确披露了跨境传输，并且告诉用户可以**关掉 AI 解释**（规则结果完全一样）。
首页也确实有这个开关（`Write plain-English explanations`）——文档没吹牛。
