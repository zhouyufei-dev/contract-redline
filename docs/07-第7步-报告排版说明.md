## 2. 三层代码，各干一件事

这是这一步唯一需要你理解的架构。**数据 → 模型 → 渲染**，一层只做一件事：

| 文件 | 干什么 | 不干什么 |
|---|---|---|
| `app/engine/scoring.py` | 把 24 条命中**合并**成 20 组；分档；算总览的四个数字 | 不写一个字给用户看 |
| `app/report/renderer.py` | 组出 `Report` 模型：卡片编号、每张卡的原句/解释/改法/话术 | 不碰 HTML |
| `app/report/html_report.py` | 把模型画成 HTML | **不做任何判断**，模型里没有的东西它一个字也不编 |

为什么非要拆开？因为下一步要做 PDF 时，`renderer.py` 一行都不用改，只多一个 `pdf_report.py`
去读同一个 `Report`；以后做网页端，后端直接把 `Report` 序列化成 JSON 给前端，还是同一份数据。

一句话记住：**`renderer.py` 是"报告里有什么"，`html_report.py` 是"长什么样"。**

## 3. 相邻条款为什么要合并（你特别要求的）

假合同里有四处是"一件事拆成两条写"：

- `4.1` 转让所有权利 + `4.2` 视为 work made for hire → 合成一张卡（R08）
- `4.3` 放弃署名权 + `4.4` 禁止作品集展示 → 合成一张卡（R09）
- `10.1` 时间是本质要素 + `10.2` 每天罚 500 美元 → 合成一张卡（R18）
- `9.1` 保密义务 + `9.2` 永久存续 → 合成一张卡（R19）

**合并必须满足三个条件，缺一不可**：① 同一条规则命中的；② 同一个大章节（都是 4.x）；③ 子条款号连续。
`4.1` 和 `4.5` 不合并（跳号，中间夹着三条别的内容）；`2.5` 和 `3.1` 不合并（跨章节）。
宁可多出一张卡，也不错误合并——**漏掉一个独立的问题，比让用户多读一段话严重得多**。

合并后卡上会同时列出两句原文，比如：

```
Sections 4.1 and 4.2   (R08, severity 10)
Section 4.1: "Contractor hereby irrevocably assigns ..."
Section 4.2: "All Deliverables shall be deemed "work made for hire" ..."
```

配的说明只针对这两句共同造成的后果（"你连没被采用的草稿也一起没了"），不会重复两遍。

**省钱的地方在这里**：24 条命中只调 20 次模型——每组只把最长的那一句送进去写解释。
第二次跑同一份合同是 0 次调用、0 token，全部走缓存。

## 4. 为什么总览上没有"82 分"

这是刻意的，不是没做完（决策记录 D-019）。

- 一条**无限赔偿**就足以让整份合同不能签。如果把它和 9 条小毛病加权平均成 82 分，
  用户会读成"还行，回头再说"——**这个数字会把最要命的那条稀释掉**。
- 而且任何权重都是我们拍的，用户告我们"你说 82 分我才签的"，我们没法自证。

所以总览只给三样东西：**一句判定语 + 四个档位的件数 + 比例条**。
所有数字都能在下面的卡片里逐条数出来，经得起核对。这是"可验证"和"看起来专业"之间我们选前者。

四个档位按**后果**命名，不按分数：`Deal-breaker 10` / `Serious 7` / `Costly 5` / `Watch 3`。

## 5. 免责声明为什么写死在代码里

`app/report/disclaimer.py` 里是两个 Python 字符串常量，`renderer.py` 无条件把它们放进报告，
**模型永远碰不到它们**。三个原因：

1. 模型写免责声明会"发挥"——写成"本报告已由律师审核"这种话，是要吃官司的。
2. 免责声明是法律文本，必须**逐字可控**、能版本化（改一个字要有记录）。
3. 用户拿这份报告去跟客户吵架时，这句话是他唯一的挡箭牌，不能因为模型抽风就消失。

它出现在**两个位置**，两处都由代码写死：

- **页眉**（第一屏右上角，小字）：`Not legal advice — software-generated screening of the text.`
  为什么页眉也要：用户可能只截第一屏发给朋友，或者打印时只印了第一页——那时候底部那句他根本看不到。
- **全文末尾**（正文和"这份报告查不到什么"之后）：完整版免责声明，一个字不删。

另外卡片区后面还有一段"**What this report cannot tell you**"（这份报告查不到什么），
写的是：只查写出来的、查不出"本该有却没有"的条款、合并过的条款要一起改、你的具体交易可能让某条变合理、
谈判措辞不是法律修改。这段也不是模型写的。

## 6. 怎么生成

```powershell
# 只出报告，不调模型（用规则自带的文案，最快，0 成本）
.\run.ps1 data\samples\fake_contract_01.docx -Scan -Html

# 带 DeepSeek 的解释（第一次会花约 1 美分，之后走缓存免费）
.\run.ps1 data\samples\fake_contract_01.docx -Scan -Html -Explain

# 生成并直接打开
.\run.ps1 data\samples\fake_contract_01.docx -Scan -Html -Open
```

输出固定在 `data/outputs/<文件名>.report.html`。**单文件**——CSS 全内联，不引用任何外部字体、
图片、JS，双击就开，发给客户不会变成一堆方块。

### 想要 PDF？

打开报告，`Ctrl+P`：

- 目标打印机选 **"另存为 PDF"**
- 纸张 **Letter**（美国客户的标准，打印样式已经按 Letter 设好）
- 边距 **默认**
- **取消勾选**"页眉和页脚"（否则浏览器会在角落印上网址和日期）

打印时卡片不会被切成两半（`break-inside: avoid`），按钮和目录表自动隐藏。

## 7. 怎么验证的（一共 56 项检查，`tools/test_report.py`）

不靠"我看着还行"，靠断言：

- **合并**：`4.1`+`4.2` 真的合成一张卡；`4.1` 和 `4.5` **不**合并；跨章节**不**合并。
- **编号**：卡片是 01…20 连续、不跳号；目录表和卡片一一对应。
- **原文**：每张卡引用的句子，必须能在合同原文里逐字找到（`mark` 高亮拆开后拼回去，必须等于原句）。
- **语言**：整份报告里不允许出现一个中文字符（D-001）。
- **结构**：HTML 标签全部正确闭合（一个没关的 `div` 会让整页排版错位）；单文件、无外链。
- **降级**：模型全挂了也能出报告——每张卡用规则自带的文案兜底，且会标注"这句话来自规则库"。
- **免责声明**：页眉那行短句、末尾那段全文，都必须逐字等于 `disclaimer.py` 里的常量（改一个字测试就红）。

`tools/test_rules.py`（297 项）和 `tools/stress_clean.py` 仍然全绿，规则大脑没被这一步碰过。

## 8. 这一版故意没做的

| 没做 | 为什么 | 什么时候做 |
|---|---|---|
| 服务端导出 PDF | 要装 GTK 或自己算坐标，Windows 上极易失败；浏览器打印够用 | 有客户抱怨"打印出来不对"时 |
| 封面 / 客户 logo / 品牌色配置 | MVP 阶段所有用户看到同一份样子，先验证有没有人买 | 有第一批付费用户后 |
| 多份合同对比、历史记录 | 需要账号体系 | 做网页端时 |
| 邮件自动发送 | 同上 | 同上 |

## 9. 这一步之后，你手里有什么

一份 20 张卡、约 60 KB 的 HTML 文件（其中一半是内联样式），双击就能打开，能直接发给客户，
内容 100% 来自用户自己的合同原文，解释 100% 经过三道护栏检查，
免责声明 100% 由代码写死。

**这就是 MVP 的交付物。** 下一步该做的不是继续加功能，而是拿它去问 10 个真实的自由职业者：
"你愿意为这个付 9 美元吗？"
