## 二、`app/` 里面（按数据流动的顺序看）

一份合同进来后，会依次经过 5 个房间。**这就是整个产品的骨架**：

```
合同文件 → [parsers] → [rules] → [engine] → [llm] → [report] → 报告
            读成文字    找出坏话    复核+打分    说人话     排版
```

| 文件 | 大白话 | 打个比方 |
|---|---|---|
| `main.py` | **总开关**。你在终端敲的那条命令，入口就是它。它负责按顺序调用下面几个房间 | 餐厅前台：接待客人，把单子传给后厨 |
| `config.py` | **唯一读 `.env` 的地方**。其他文件想要 Key，都来问它 | 财务室：只有它能开保险柜 |
| `parsers/extractor.py` | 把 PDF/DOCX **变成纯文字**。第 3 步我们就要写它 | 拆快递：把箱子里的东西拿出来摊平 |
| `parsers/__init__.py` | 空壳文件，只为让 Python 认这个文件夹是个"包"。以后每个文件夹都有，不用管 | 门牌 |
| `engine/textnorm.py` | **文字清洗**。PDF 抽出来的字很脏：句子被换行切断（`con-` + `tract`）、每页都有重复页眉页脚、引号是弯的。不洗干净，后面的规则会漏抓 | 洗菜 |
| `engine/matcher.py` | **核心匹配器**。拿规则去文字里找；找到后干最要紧的一件事：看前面几个词有没有 `not` / `except`——因为合同里大量写着"**不**承担……责任"，naive 的做法会报出完全相反的意思 | 质检员：不光看有没有，还看是不是反话 |
| `engine/scoring.py` | **打分和排序**。20 条全中不能给个 160 分（用户看不懂）。要去重、排序、只展开最狠的 3 条 | 医生写诊断：先说最要命的 |
| `rules/redlines_us.py` | **20 条红线本身**，纯数据（一串清单），不含逻辑。加一条规则 = 加一段数据，不用改程序 | 一本"通缉令"相册 |
| `llm/deepseek_client.py` | 唯一跟 DeepSeek 说话的地方。**它只负责"解释"，永远不负责"判断有没有风险"** | 翻译官：不参与判案，只负责把判词讲成大白话 |
| `llm/guards.py` | **护栏**。模型说完话先过它这一关：引用的原话必须真在合同里、金额不许自己编、不许说中文/法条/"这很标准"。不过关就打回重写 | 校对：把翻译官编出来的例子当场划掉 |
| `report/renderer.py` | **排版**。把"原文引用 + 为什么是坑 + 怎么改"拼成一份能看的报告 | 印刷厂 |
| `report/disclaimer.py` | **免责声明，写死在代码里**，不交给 AI 生成。理由：AI 偶尔会"忘记"写，而这个东西漏一次就是法律风险 | 合同背面的固定小字 |

## 三、另外三个文件夹

| 路径 | 大白话 |
|---|---|
| `prompts/card_en.md` | 给 AI 的唯一一份指令：你只负责解释这一条、输出 5 个字段（why / fix / ask / fallback / walk_away）、别自己加新发现、别用行话、字数上限。**改说话风格只改这个文件，不用动代码** | 台词本 |
| `data/samples/` | **放测试用合同的地方**。第 3 步你需要一份 PDF 或 DOCX 放进来，代码才有东西可读 |
| `data/outputs/` | 生成的报告和抽取出来的文字存这儿（`*.scan.txt` 就是一次完整扫描结果） |
| `data/cache/llm/` | 模型说过的话的缓存。同一份合同第二次跑**一分钱不花**；里面存的是合同原文碎片，上线前要和隐私策略一起定清理规则 |
| `tests/` | 以后写自动测试。重点测一种情况：`shall not be liable` 这种**否定句不能被误报成风险** |

## 三·五、`tools/` 里面（开发工具，不是产品）

| 文件 | 干什么 |
|---|---|
| `build_docx.ps1` | 把 `.txt` 合同打包成真的 `.docx`（一次性用过） |
| `verify_docx.ps1` | 检查生成的 docx 是不是合法 Word 包 |
| `build_pdf.py` | 把 `.txt` 合同渲染成真 PDF，用来测 PDF 解析 |
| `check_step3.py` | **验收脚本**：读文件 → 检查 19 条红线是否都还在、3 个陷阱句是否原样保留、错误处理是否正常 |
| `check_pdf_quality.py` | 量化 PDF 抽取对文字的"破坏程度"（见下） |
| `diff_texts.py` | 排错用：逐字符比对 docx 和 txt |
| `requirements-dev.txt` | 工具专用的依赖（fpdf2），产品本身不需要 |
| `scan_to_file.ps1` | 跑一次扫描，把结果按 UTF-8 存进 `data/outputs/scan.txt`（PowerShell 默认重定向是 UTF-16，编辑器打不开） |
| `test_rules_step4.py` | **规则回归测试**。51 项检查：假合同标准答案 + 否定句 + 跨规则隔离 + 干净合同零误报 |
| `llm_smoke.py` | 只发 **1 次**真实请求的体检：Key 通不通、模型名对不对、单条多快、多少 token |
| `test_llm.py` | **LLM 层离线测试，45 项，不联网不花钱**：护栏、JSON 解析、重试降级、缓存、Key 不泄露 |
| `show_cards.py` / `inspect_cache.py` / `drop_cache.py` | 抽查缓存里的卡、找出哪张被护栏打回过、删掉某一条的缓存强制重问 |

### 第 3 步实测出的一个重要数字

| 来源 | 直接匹配命中 | 空白归一后命中 |
|---|---|---|
| `.txt` | 19/19 | 19/19 |
| `.docx` | 19/19 | 19/19 |
| `.pdf` | **17/19** | **19/19** |

意思是：**PDF 抽出来的文字，有 2 条红线因为被换行切断而"看不见"了**。
这就是 `engine/textnorm.py` 必须存在的原因——规则写得再准，喂进去的文字是断的也白搭。
第 4 步实测：**PDF 已经追平 DOCX，都是 3/3**（R01 / R02 / R05 全部命中，且陷阱句 3.2 被正确拦下）。

## 四、你现在最该记住的三件事

1. **`.env` 里的 Key 永远不要粘到聊天窗口、截图、或任何在线文档里。** 它已经进了 `.gitignore`，这是保护你的第一道门。
2. **改规则不用改代码。** 想调一条红线，只动 `rules/redlines_us.py`；想调 AI 语气，只动 `prompts/`。
3. **判断归代码，解释归 AI。** 这条线一旦破了，"零幻觉"的承诺就没了。
